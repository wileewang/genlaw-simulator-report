DESIGN UPDATE · 2026-11-09

系统设计调整：两阶段 + 结构化工艺计划

在用真实零件摸底后，我们重新梳理了系统分层。本节说明三件事：设计怎么变了，每个环节怎么验证，以及因此需要先准备什么数据。状态：方向已确定；新增和调整的部分都待开发，现有的 FreeCAD → CAMotics 链路继续沿用。

  1. 系统设计变了分两个阶段：先出工艺卡，再从工艺卡到仿真加工。中间新增“结构化工艺计划”作为正式接口。
  2. 每层都要能单独验证每一层要有标准答案。整体出错时，能定位到是哪一层出了问题。
  3. 因此要先准备数据结构化工艺计划是新模块，没有现成参考。要先定义格式，人工写出标准答案，并请工艺工程师核对。

1　新的系统分层

程序需要 agent 判断关键中间结果
第一阶段：从图纸到工艺（里程碑一：工艺卡可交付）三视图→① 几何理解→CAD + 公差 + 粗糙度→② 工艺规划→工艺卡（给人看）结构化工艺计划（给机器用）
外部入口：已有的真实工艺卡工艺卡 PDF + CAD→读卡（本地 OCR + 规则）→③ 工步与 CAD 特征对应→结构化工艺计划
第二阶段：从计划到仿真加工（里程碑二）结构化工艺计划→④ 加工准备→可执行方案（JSON）→NC 生成（FreeCAD）→⑤ 仿真（CAMotics）→与 CAD 比对
自动迭代比对得到差异清单→参数、刀路问题：回到 ④，由程序自动修正·工艺路线不可行：回到 ②

和原设计相比的变化：

  • 工艺规划除了工艺卡，还要输出一份结构化工艺计划。工艺卡是给人看的，省略了很多指代，例如没写清“铣 R6 圆弧”是图上哪一处 R6。规划时这些信息本来是清楚的，所以直接写进计划，第二阶段就不需要再猜。
  • 原来的“加工准备”拆成两部分：③ 理解卡片、把工步对应到 CAD 特征，需要 agent；④ 选刀、定参数、定刀路策略，由程序完成。
  • 只有外部的真实工艺卡才需要 ③ 的 agent。系统自己规划出来的工艺，直接带着特征编号进入第二阶段。
  • 第二阶段从结构化计划开始全部是程序，开发时不依赖 agent。
  • 迭代环写成明确的一环，并规定好出了问题该回到哪一层。

2　每个环节怎么验证

只做端到端闭环，最后只能知道“这个零件没做对”，不知道错在哪一层。所以每一层都要有标准答案，并能单独测试：

层测试时的输入（标准答案）输出和什么比看什么
① 几何理解图纸真实 STEP、图上的公差形状差异（IoU）、特征有没有漏、公差读得对不对
② 工艺规划真实 STEP + 公差真实工艺卡、黄金计划每个特征都有工步负责；公差都有工步保证；顺序可行。
不要求和真实卡逐字一致，因为正确的工艺不止一种
③ 工艺卡转计划真实工艺卡 + STEP黄金计划工步对应到的特征对不对
④ 计划 → NC黄金计划真实 CAD仿真结果和 CAD 是否一致，关键尺寸是否在公差内
⑤ 仿真器本身结果已知的简单 NC解析计算的形状仿真器有没有算错

替换法定位。端到端不合格时，从上游开始，逐层把输出换成标准答案再跑。哪一层换完结果变好，问题就在哪一层。这套过程会做成程序自动执行。

全自动：            图纸 → ①几何 → ②规划 → 计划 → ④NC → ⑤仿真    ✗
换掉 ①：                 真实 STEP → ②规划 → 计划 → ④ → ⑤        ✓  → 问题在 ①
换掉 ①②：                         黄金计划 → ④ → ⑤                ✗  → 问题在 ④⑤

编号贯穿。比对时，差异按 CAD 特征报告，例如“F12 多料 0.4 mm”。从 F12 能查到负责它的工步，再查到这个工步来自卡片的哪一行，或规划时的哪条决策。还可以按工步逐个仿真，检查每一步只去掉了目标特征的材料。

3　对数据的要求

手上已有一批真实零件的工艺卡和对应 CAD。各层标准答案的情况如下：

层的输出标准答案
CAD、公差、粗糙度有：真实 STEP 和图纸
工艺卡有：真实工艺卡
结构化工艺计划没有。这是新增的中间层，需要人工补齐（见下一节）
加工后的形状有：真实 CAD

4　新增模块：结构化工艺计划

这个格式把工艺卡的内容写成程序能直接读的数据。每一步都写明加工 CAD 上的哪些特征，不留需要人去理解的指代。

包含：做什么
  • 引用的 CAD，以及 CAD 特征编号表
  • 毛坯：材料、形状、尺寸
  • 装夹：基准、夹持位置、朝向
  • 工序和工步：加工类型、加工哪些特征、做到尺寸还是留余量、先后顺序
  • 要求：尺寸公差和粗糙度，并注明来源（图纸或工艺卡）
  • 非切削工步：只记录，仿真时跳过
不包含：怎么做
  • 用什么刀
  • 转速和进给
  • 刀路怎么走
  • 分几层切

这些由 ④ 加工准备的程序决定。结果有问题时，迭代环会自动调整。

工步示例（示意，非真实零件）：

{
  "step_id": "OP20-S3",
  "operation": "contour_mill",      // 加工类型
  "setup": "SETUP-2",               // 第几次装夹
  "targets": ["F12", "F13"],        // 加工 CAD 上的哪些特征
  "requirements": [{"feature": "F12", "type": "radius",
                    "nominal": 6.0, "tol": [0.0, 0.1]}],
  "leave_stock_mm": 0,              // 做到尺寸
  "depends_on": ["OP20-S2"]
}

和标准的关系。STEP-NC（ISO 14649）、STEP AP224 和 AP240 都有类似概念，但都太重，开源工具也很少，而且 STEP-NC 把刀具和参数也放在里面。所以我们自定一种精简的 JSON 格式，特征类型、层级（工艺计划 → 装夹 → 工步 → 特征）和术语参照 ISO 14649，公差分类参照 ISO GD&T。第一版先只覆盖铣削。

需要工艺工程师核对。人工写出的计划（“黄金计划”）是所有分层验证的基准，必须由工程师确认。我们会为工程师准备专门的核对页面，不需要读 JSON。每个工步一行：

  • 左边是卡片原文；
  • 中间是 CAD 上高亮出的、这一步要加工的特征；
  • 右边是计划内容的中文表述。

工程师逐项选择“对 / 不对 / 不确定”，可以写意见。核对页面只私下分享，不放到本站。工程师确认之前，计划只算草稿答案，可以用于开发，但不能作为正式验收依据。

最终与中间剩料均已仿真

CAMotics 按同一 NC 连续去料，与原 CAD 比较最终形状；工步边界另外检查实际剩料。IoU、特征几何与工序一致性分别判定。

输出

参数由谁确定，缺项怎样处理？
  • 卡上明确规定：作为约束传递；修改须回到工艺规划或工艺师傅。
  • 资源提供：引用有版本的毛坯、设备、刀具、夹具及坐标配置。
  • 程序 / CAM 推导：记录依据、输入、规则或引擎版本；只能在已定义的工艺与能力范围内选择。
  • 无法确定：明确缺什么、影响哪步、交给谁处理；不得静默补默认值。

缺关键执行数据阻止对应 NC 生成；缺验收依据阻止对应质量判定。范围和前置条件必须明确，软件就绪与工艺批准分别记录。

工艺衔接定义 ↓

扩展与验收约定
  • 新尺寸/孔位等变体由数据驱动，主流程没有零件编号分支。
  • 新组合保持实际剩料连续，单位、坐标与要求绑定一致。
  • 不支持的工艺、设备语义或精度在执行前报告；检验不足时返回不可判定。
  • 新增能力通过小型独立正常/错误案例，同时保留旧能力的回归结果。
  • 工艺卡约束与派生参数来源可追溯；缺项和资料冲突在受影响阶段拦截，不复用历史案例默认值。
  • 工步与最终/中间要求分别报告；非几何或未支持步骤不被误计为整卡完成。

目标是将修改集中在适配器、配置和必要的版本演进，并用测试证明兼容；不承诺任何新零件都无需算法开发或永远无需调整公共接口。
