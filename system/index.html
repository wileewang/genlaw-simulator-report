新零件来了，怎样扩展？

设计已定义 · 运行框架待实现

零件集合影响能力开发优先级；统一接口、原始数据与验收约定持续复用。

01 / 扩展约定

统一数据与流程

CAD、制造要求、工艺卡、资源配置和结果约定持续复用；格式变更带版本与迁移。

02 / 扩展约定

可替换的工艺与工具

编程、设备后处理、去料/成形、几何检验各有适配接口。FreeCAD 与 CAMotics 是首批实现。

03 / 扩展约定

可核对的支持范围

分别记录每一步支持的工序、坐标/指令、材料表示与精度；执行前检查整条链是否具备能力。

  1. 提取所需能力
  2. 匹配整链支持范围
  3. 复用配置或新增适配
  4. 运行新旧验收用例
新需求的扩展位置与验收条件
变化扩展位置怎样验收
新尺寸、孔位或数量使用已有能力，换 CAD 与工艺卡参数在已验证范围内运行；超尺寸、精度或资源预算明确返回缺项。
新的特征组合复用工序，增加编排与实际剩料交接验证顺序、换刀、坐标与工序间材料连续性。
新机床或控制器同类机床换配置；新轴链或 NC 方言增加适配器后处理与 NC 解释分别验证，不能仅换机床名称。
新工艺，例如车削增加编程、仿真后端及所需检验项沿用公共接口和结果页；新算法仍须开发与独立验证。
展开适配接口、能力声明与兼容约定

以下是模块 2 / 3 内部的扩展接口设计，不增加一级模块。现有 S1 的通用适配与能力匹配仍待实现。

GeometryPacket

cad_ref: 原文件、版本、哈希、单位、坐标；features / requirements: 稳定关联、原始标注与不确定项

引擎内部面编号不直接充当长期特征ID；转换后的网格不替换原始验收CAD。

OperationPlan

operation.type + version: 工艺类型与版本；parameters: 类型对应的参数、工序依赖、目标特征；resources: 来料、刀具、刀柄、装夹、设备与控制器引用

工序类型可扩展，禁止按零件文件名或71份清单编号选择实现。外购、预成形与加工明确分流。

ProgramArtifact

program_ref: 类型、方言、单位、文件哈希；resolved_config: 实际设备、坐标和刀长约定；provenance: 工艺卡、CAD、适配器、引擎与后处理版本

当前NC主线保留最终NC；非NC工艺将来使用明确的其他程序类型。FreeCAD Job 属于适配器内部产物。

MaterialState

geometry_ref: 实体/网格等表示与版本；frame / units / precision: 坐标、单位与表示误差；material_ref / parent_state / operation_ref: 材料、前一状态和来源工序

不同后端交换实际材料状态；格式转换声明误差和可支持范围，禁止从目标CAD重造中间材料。

VerificationResult

geometry_metrics: IoU、过切/欠切等指标与适用方法；requirement_results: 逐项通过、失败、未验证或不可判定；evidence_refs: 程序、材料、资源、比较器和回放来源

检验接口与引擎分离；局部精度不足时不能仅凭整体IoU判通过。

适配器分工

  • CAM adapter：工序、CAD、资源 → 刀路/工艺程序；FreeCAD Job 不向上游泄漏
  • Machine / post adapter：刀路与资源 → 目标方言的最终NC；设备参数与后处理分开记录
  • Simulation adapter：最终程序与配置、实际来料 → 实际加工状态；保留控制器语义和材料来源
  • Verification adapter：原始CAD/要求 + 实际结果 → 适用指标和逐项判定

能力声明

只有编程、后处理、仿真和所需检验都在已验证范围内，才能声明该任务受支持；单步有能力不等于整链受支持。

  • 接口版本化，新增类型明确声明；旧卡片通过有记录的迁移保持可追溯。
  • 工艺特有参数使用有类型的扩展区，核心不假定只有铣削、Z向刀轴、矩形毛坯或单一网格。
  • 几何变换、单位、刀长与坐标由配置明确传递，不能依赖工具隐含默认值。
  • 统一输入输出不意味着统一所有物理模型；新增成形或材料物理允许独立求解器。

目标是将修改集中在适配器、配置和必要的版本演进，并用测试证明兼容；不承诺任何新零件都无需算法开发或永远无需调整公共接口。

加工编程

当前开发范围

把工艺卡映射成 CAM 任务，计算刀路，再按选定控制器规则导出最终 NC。

输入 / INPUT

process_card

有序工序、刀具、装夹、坐标与参数

cad_ref

原始 CAD；同一版本也传递给仿真验收

resource_profile

设备能力、NC 方言、毛坯、工具 / 夹具几何

输出 / OUTPUT

nc_ref

最终 NC 文件及其哈希、后处理器版本

machining_config

解析后的毛坯、刀具、坐标变换、控制器语义与夹具

provenance

工艺卡、CAD、CAM 软件与配置版本的绑定

issues

不支持工序、超出能力、单位或引用错误

仿真检验

当前开发范围

从真实声明的毛坯执行 NC，保存剩余材料，并在同一坐标系下与原始 CAD 比较。

输入 / INPUT

nc_ref

模块 2 导出的同一份最终 NC

machining_config

实际毛坯、刀具、装夹 / 坐标与所需控制器语义

target_ref / requirements

未经改写的目标 CAD 与制造要求

输出 / OUTPUT

result_geometry

实际加工后的实体 / 网格，注明数据格式

metrics

体积 IoU、过切 / 欠切等指标及计算方法 / 精度

requirement_results

逐项要求的通过、失败、未验证或不可判定状态

replay / provenance

保存的加工状态、轨迹、NC / 配置 / 结果哈希与错误反馈

通用接口约定与完整定义
  • CAD 与制造要求的原始版本贯穿整条流程。
  • 文件引用包含版本与哈希；单位、坐标和刀长语义必须一致。
  • 工艺卡可以来自固定测试输入、人工或未来的 Agent，使用同一接口。
  • 不支持、缺信息或精度不足时显式返回状态，不能自动视为通过。
  • 几何指标不代替粗糙度、材料物理、夹紧力或真实机床验证。
  • 模块2/3按明确适配接口扩展，执行前匹配整链能力，新增能力须通过新旧用例验收。
  • 外部纸质工艺卡保留原文、版次与字段位置，按有版本的字段和语义映射转为内部输入；缺项不得静默填默认值。

当前参考案例调用 FreeCAD 自带的 linuxcnc_post 导出 NC。它是后处理器名称；此链路没有安装或运行 LinuxCNC。
